# 01 · 设计目标与设计原则

> 下一篇：[02 总体架构与模块划分](02-总体架构与模块划分.md) ｜ 风格：[STYLE.md](../STYLE.md)

本篇回答两个问题：**xmedia-kit 要达成什么**（每条带验收度量的目标表），以及**编码时的争议拿什么裁决**（十三条设计原则）。
早期的 legacy 代码剖析卷已随迁移叙事移除；由那份剖析推导出的目标与原则在此保留。

## 1. 设计目标（每条带验收度量）

| # | 目标 | 度量方式（可验收） |
|---|---|---|
| G1 | **单一职责**：文件 ≤ 500 行，类 ≤ 12 个 public 方法，函数 ≤ 80 行 | `check_invariants.py` C1/C2/C3，超标即 CI fail |
| G2 | **核心与 FFmpeg 隔离**：`base/` `media/base/` `player/public/` 不含任何 `libav*.h` | C4 grep + `nm -D` 符号检查 |
| G3 | **核心与平台隔离**：`base/` `media/` `player/` 中平台宏与平台头出现次数 = 0 | C5 grep |
| G4 | **编译期安全**：选项/事件/状态/时间全部强类型；字符串选项仅作为兼容入口且经注册表校验 | `OptionRegistry` 对未知 key 返回错误；`-Wconversion -Wold-style-cast` 开启 |
| G5 | **无手工资源管理**：核心代码中 `new`/`delete`/`malloc`/`free` = 0（白名单：`base/memory/`） | C7 grep |
| G6 | **可取消/不卡死**：`Player::~Player()` 最坏耗时上界可测（目标 < 500ms） | 压力测试：10000 次 prepare/stop + 阻塞网络 |
| G7 | **可测试**：核心逻辑 100% 可在无媒体文件、无实时时钟、无显示、无声卡的条件下单测 | 覆盖率：核心行覆盖 ≥ 85%，`sync` 类模块 100% |
| G8 | **行为对齐**：与原版 legacy 在相同输入下逐帧一致 | Golden Test 帧哈希/音频校验和对拍 |
| G9 | **性能不回退**：首帧耗时、CPU、内存不劣于原版 | `tests/bench` + CI 趋势守护 |
| G10 | **构建简洁**：一条 `cmake --preset` 完成，无 shell 脚本前置 | `docs/BUILDING.md` + CI |
| **G11** | **风格统一**：全面遵循 Google C++ Style + Chromium 工程约定 | `.clang-format` + `.clang-tidy` + `cpplint` + C17（后缀必须 `.cc`）+ C18（禁异常） |
| **G12** | **Linux 出画**：X11 与 Wayland 上流畅播放 1080p30，双后端（SDL2 + 原生 GL）均通过契约测试与 xvfb 端到端验收 | CI `e2e-linux` job（见 [09 §9](09-Linux平台实现方案.md)） |
| **G13** | **SDK 友好**：新人 15 分钟内从 clone 到出画；每条错误信息含 summary+detail+suggestion | `examples/play_sdl2/main.cc` 行数 + 错误消息三段式抽查 |

### 非目标（明确不做）

- ❌ 不重写 FFmpeg。解复用/解码能力照用。
- ❌ 不做宿主 UI 组件（播放器只出画面/回调，视图层归宿主）。
- ❌ 设计期不内建边下边播缓存（后由字节级文件缓存装饰器另行落地）。
- ❌ 首期不做 C ABI 兼容层（已选现代 C++ API）。
- ❌ 不做 DRM / CDM（`media/base/cdm_context.h` 只留空接口位）。
- ❌ 不做 Android / iOS 后端（本次范围是 Linux；接口已冻结，后续增量）。
- ❌ 不内建 libass 字幕排版（输出 `raw_ass` 交上层）。
- ❌ 不追求 100% legacy option 行为等价（URL 重写钩子重新设计成显式拦截器，Δ11）。

## 2. 十三条设计原则（编码时的裁决依据）

后续所有争议都拿这十三条判。P1–P10 是通用架构原则，**P11–P13 是本次新增的风格与参照原则**。

**P1 · 依赖倒置**
上层定义接口，下层实现。`RendererImpl` 依赖 `media::VideoDecoder` / `VideoRendererSink`，不依赖 `FFmpegVideoDecoder` / `GlVideoRendererSink`。构造时通过 `Deps` 注入。

**P2 · FFmpeg 是插件，不是地基**
`AVFormatContext` / `AVCodecContext` / `AVFrame` / `AVPacket` 只允许出现在 `media/ffmpeg/` 与 `media/filters/ffmpeg_*`。跨边界一律转换成 `media::DecoderBuffer` / `media::VideoFrame`。

**P3 · 值语义优先，共享语义显式**
`DecoderBuffer` / `VideoFrame` / `AudioBuffer` 用 `scoped_refptr`（Chromium 约定），配置与事件用值类型。独占所有权用 `std::unique_ptr`，非拥有用 `raw_ptr<T>` 或 `T&`。**永不裸指针表示所有权。**

**P4 · 不跨模块抛异常，且全局禁用异常**
Google/Chromium 规定：`-fno-exceptions -fno-rtti`。模块边界返回 `base::expected<T, MediaError>` + `RETURN_IF_ERROR` / `ASSIGN_OR_RETURN`。`CHECK()` 用于不可恢复的编程错误，`DCHECK()` 用于 debug 断言。理由详见 [STYLE §3.1](../STYLE.md)。

**P5 · 时间是强类型**
禁止裸 `int64_t` 表示时间。统一用 `base::TimeDelta`（媒体时长）、`base::TimeTicks`（单调墙上时钟）、`base::Time`（Unix 时间），与 Chromium 完全一致。`media::kNoTimestamp` 是显式哨兵常量，不是魔法值 `INT64_MIN`。

**P6 · 时间可注入**
所有需要"当前时间"的地方走 `base::TickClock`。生产用 `base::DefaultTickClock`，测试用 `base::SimpleTestTickClock`（手动推进）与 `base::test::TaskEnvironment`（`TimeSource::MOCK_TIME`）。**这一条直接决定了 `VideoFrameCompositor` 能否单测。**

**P7 · 状态显式化**
播放状态用 `StateMachine` + 迁移表管理，不允许散落 `if (state == X)`。每个非法迁移记录日志并返回错误，而不是静默忽略。

**P8 · 阻塞必须可取消，跨 sequence 只 PostTask**
所有阻塞等待走 `base::WaitableEvent::TimedWait`。跨 sequence 通信**只**通过 `PostTask` + `base::BindOnce` + `WeakPtr`，绝不直接调用另一个 sequence 拥有的对象方法。这是消除 R11（对象已析构但任务还在队列里）的结构性手段。

**P9 · 数据流单向，控制流反向**
数据（Buffer→Frame→Sink）沿管线单向流动，用有界队列解耦。控制（seek/pause/flush）反向传播，通过 `serial` 世代号 + `base::AtomicFlag` 实现，不允许跨 sequence 直接改对方状态。

**P10 · 性能敏感处显式标注**
每帧都会走的路径（`VideoFrameCompositor::DecideNextFrame`、`AvSyncController::GetMasterClock`、`AudioRendererSink::RenderCallback::Render`）标注 `// @hot`，禁止在其中做内存分配、日志、粗粒度加锁。用基准测试守护（见 [04 §8](04-线程模型与数据流.md)）。

**P11 · ★Google C++ Style 是硬约束，不是建议**
`.clang-format`（`BasedOnStyle: Google`、80 列、2 空格）+ `.clang-tidy`（`google-*` `modernize-*` `performance-*` `bugprone-*`）+ `cpplint` 三重把关。命名规则：类型 `CamelCase`、方法 `CamelCase()`、getter `snake_case()`、成员 `snake_case_`、常量 `kConstant`、文件 `lower_snake_case.cc`。违反即 CI fail。完整规则见 [STYLE.md](../STYLE.md)。

**P12 · ★Chromium `media/` 是设计参照与裁决依据**
目录结构（`media/base/` 接口 + `media/filters/` 实现）、类名（`DecoderBuffer` / `VideoFrame` / `DemuxerStream` / `VideoDecoder` / `Renderer` / `Pipeline` / `VideoFrameCompositor` / `AudioRendererSink` / `DecoderStream` / `DecoderSelector` / `MediaLog`）、接口签名（`Decode(buffer, DecodeCB)`、`Read(count, ReadCB)`、`Render(delay, delay_ts, glitch, AudioBus*)`）全面对齐。设计分歧时，**默认答案是"Chromium 怎么做我们就怎么做"**，偏离必须写明理由（如 D3 解复用线程模型、Δ17 变速算法）。

**P13 · ★SDK 视角优先于实现视角**
公开 API 的每一个形状都要过人体工学审查：最短出画路径、可操作错误、值语义优先。判据：**`examples/play_sdl2/main.cc` 的行数**（目标 ≤ 300）与 **新人冷启动时间**（目标 ≤ 15 分钟）。若为了内部实现方便而让公开 API 变复杂，改内部实现。

## 3. 保留什么（避免为了重写而重写）

legacy 里有大量经过十年线上验证的**算法与调参经验**，必须原样继承：

| 必须继承的资产 | 原位置 | xmedia-kit 去向 | 为什么不能动 |
|---|---|---|---|
| 音视频同步算法（`compute_target_delay` + `synchronize_audio_to_video`） | `ff_ffplay.c` | `media/filters/video_frame_compositor.cc` + `av_sync_controller.cc` | ffplay 十余年演进，含大量经验阈值 |
| 三级高水位缓冲（first/next/last-high-water-mark-ms） | `read_thread` | `player/buffer_controller.cc` | 弱网起播速度的核心调参，B 站线上验证过 |
| 丢帧策略（`framedrop` / `max-fps`） | `video_refresh` | `VideoFrameCompositor::DecideNextFrame` | 低端机流畅度关键 |
| 精确 seek（`enable-accurate-seek` + timeout 兜底） | `ff_ffplay.c` | `player/seek_controller.cc` | 用户可感知体验 |
| **`serial` 世代号机制** | `PacketQueue`/`FrameQueue` | `DecoderBufferQueue` / `VideoFrameQueue` | seek 正确性的基石，设计极精巧（见 [04 §4](04-线程模型与数据流.md)） |
| A/V 起播对齐（`sync-av-start`） | `ff_ffplay.c` | `BufferController` + `AvSyncController` | 避免开头音画不同步 |
| 各类经验阈值常量 | `ff_ffplay_def.h` 顶部 `#define` | `media/base/media_constants.h` | 用 `tools/extract_constants.py` 提取，**禁止手抄** |

**原则**：重构改变的是**代码的组织方式与类型安全**，不改变**算法与参数**。凡涉及阈值的改动，一律走 Golden Test + A/B 基准，不凭感觉。

**唯一例外**：变速音频从 SoundTouch 换成自研 WSOLA（`AudioRendererAlgorithm`，对齐 Chromium），这是 Δ17，需要 A/B 音质验证。

## 4. 风险预判

| 风险 | 等级 | 缓解 |
|---|---|---|
| **R1** 音视频同步移植出错，偶发不同步 | 🔴 高 | Golden Test 逐帧比对 + `DecideNextFrame` 纯函数行覆盖 100% + `SimpleTestTickClock` + M6 逐行走查 |
| **R2** 自研 `base/` 工期超支（`bind.h` / `message_pump_epoll` / `TaskEnvironment` 三块最难） | 🔴 高 | 四级降级预案（L0–L3），最坏用 `SimpleTaskRunner`（~300 行）占位，**接口形态不变**，调用方零改动 |
| **R5** 析构/stop 死锁（原版顽疾重犯） | 🔴 高 | 固定销毁顺序 + `WaitableEvent::TimedWait` 超时兜底 + `WeakPtr` 结构性消除残留任务 + 4 项压力测试 |
| R3 抽象层性能回退（虚函数、`scoped_refptr`、variant、`PostTask`） | 🟠 中 | 性能预算表进 CI 门槛；`final` 促进 devirtualization；`-flto`；热路径零分配 |
| R6 FFmpeg 多版本差异（4.4~8.x） | 🟠 中 | 兼容层集中在 `media/ffmpeg/compat.h`（C8 强制），CI 跑 4 个版本 |
| R16 Wayland 嵌入模式的事件队列隔离做错 | 🟠 中 | [09 §3.1](09-Linux平台实现方案.md) E1–E3 铁律 + 独立 `wl_event_queue` + GTK4 宿主实测 |
| R17 Linux 发行版碎片化（GL 驱动 / 音频服务 / 合成器差异） | 🟠 中 | dlopen 多候选名 + 后端自动探测与优雅降级 + `xmedia-inspect doctor` |
| R8 许可证（逐行移植算法是否构成衍生作品） | 🟠 中 | 移植算法文件保留 LGPL-2.1 头并单独归目录；其余 BSD-3；法务确认 |
| R9 缓存装饰器后置导致业务无法迁移 | 🟠 中 | `media::DataSource` 接口 M4 冻结 + 首期提供内存缓存装饰器 |
| R15 工期低估 | 🟡 中 | 里程碑切分，每阶段有可运行产物，可随时停在某个 M 交付 |
