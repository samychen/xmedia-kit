## 消除 media/ffmpeg 与 base 的重复函数定义

**起因**：用户指出树里还有重复定义的函数（例子是 `BytesPerSample`），要求统一抽象到公共层。

**扫描方法**（两步，先名字后函数体）：
1. 正则抓所有 `.cc` 的自由函数定义（排除 `Class::` 成员），同名多处的列为候选；
2. 对候选函数体做「去注释 → 空白归一 → md5」，跨文件哈希相同 = 逐字重复。

结论：`BytesPerSample` / `IsPlanar` / `ToAvPixelFormat` / `FromAvPixelFormat` /
`SampleFormatFromAV` / `ToAvSampleFormat` / `Ctx` 共 7 个函数、分布在 9 个文件。

**新建 `media/ffmpeg/ffmpeg_util.{h,cc}`**，收纳四类 AV↔media 类型桥：
`ToAvPixelFormat` / `FromAvPixelFormat(fmt, fallback)` / `ToAvSampleFormat` /
`FromAvSampleFormat(fmt, fallback)` / `AsFormatContext(void*)`。
两个 `From*` 加 `fallback` 参数，是因为原来两份的唯一差别就在未映射时返回什么
（probe 用 `kUnknown`，decode 用「上一个已协商格式」），用一个表同时满足两种语义。

**`media/base/audio_parameters.{h,cc}` 补 `SampleFormatIsPlanar`**（
`SampleFormatBytesPerChannel` 本来就有），ffmpeg 侧两份 `BytesPerSample`/
`IsPlanarFormat` 全删、改调 base。**顺带修掉一个真 bug**：`ffmpeg_audio_filter.cc`
那份 `BytesPerSample` 的 `case` 列表漏了 `kS32P`，落进 `default` 返回 **0 字节**
（decoder 那份是 4）。两份拷贝最终确实分叉了 —— 这正是把它们合并的理由。
`audio_buffer.cc` 那条独立路径也因此不再与 filter 侧口径不一致。

**`video_convert.{h,cc}` 删掉导出的 `AvPixelFormatFromVideoFormat`**，
三个消费者（video_filter / image_snapshot / transcode encoder）改调
`ff::ToAvPixelFormat`。这个函数与 ffmpeg_video_decoder.cc 的匿名 `ToAvPixelFormat`
是同一张表。

**新测试 `tests/unit/media_ffmpeg/ffmpeg_util_unittest.cc`**（7 条）：
双向映射逐项对拍、`kYV12`/`kYUY2`/`kYUV420P10` 的刻意不映射、`YUV422P/YUV444P`
降级到 `kI420`、fallback 语义（同一个未映射输入、两个不同 fallback 各回各的）。
**负向验证过**：把 `kRGB565` 临时改成返回 `AV_PIX_FMT_RGB24`，测试立刻红；已还原。
