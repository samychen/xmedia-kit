## 消除 media/ffmpeg 与 base 的重复函数定义

**起因**：用户指出树里还有重复定义的函数（例子是 `BytesPerSample`），要求统一抽象到公共层。

**扫描方法**（两步，先名字后函数体）：
1. 正则抓所有 `.cc` 的自由函数定义（排除 `Class::` 成员），同名多处的列为候选；
2. 对候选函数体做「去注释 → 空白归一 → md5」，跨文件哈希相同 = 逐字重复。

结论：`BytesPerSample` / `IsPlanar` / `ToAvPixelFormat` / `FromAvPixelFormat` /
`SampleFormatFromAV` / `ToAvSampleFormat` / `Ctx` 共 7 个函数、分布在 9 个文件。

**新建 `media/ffmpeg/ffmpeg_util.{h,cc}`**，收纳四类 AV↔media 类型桥：
`ToAvPixelFormat` / `FromAvPixelFormat(fmt, fallback)` / `ToAvSampleFormat` /
`FromAvSampleFormat(fmt, fallback)` / `AsFormatContext(void*)`。
两个 `From*` 加 `fallback` 参数，是因为原来两份的唯一差别就在未映射时返回什么
（probe 用 `kUnknown`，decode 用「上一个已协商格式」），用一个表同时满足两种语义。

**`media/base/audio_parameters.{h,cc}` 补 `SampleFormatIsPlanar`**（
`SampleFormatBytesPerChannel` 本来就有），ffmpeg 侧两份 `BytesPerSample`/
`IsPlanarFormat` 全删、改调 base。**顺带修掉一个真 bug**：`ffmpeg_audio_filter.cc`
那份 `BytesPerSample` 的 `case` 列表漏了 `kS32P`，落进 `default` 返回 **0 字节**
（decoder 那份是 4）。两份拷贝最终确实分叉了 —— 这正是把它们合并的理由。
`audio_buffer.cc` 那条独立路径也因此不再与 filter 侧口径不一致。

**`video_convert.{h,cc}` 删掉导出的 `AvPixelFormatFromVideoFormat`**，
三个消费者（video_filter / image_snapshot / transcode encoder）改调
`ff::ToAvPixelFormat`。这个函数与 ffmpeg_video_decoder.cc 的匿名 `ToAvPixelFormat`
是同一张表。

**新测试 `tests/unit/media_ffmpeg/ffmpeg_util_unittest.cc`**（7 条）：
双向映射逐项对拍、`kYV12`/`kYUY2`/`kYUV420P10` 的刻意不映射、`YUV422P/YUV444P`
降级到 `kI420`、fallback 语义（同一个未映射输入、两个不同 fallback 各回各的）。
**负向验证过**：把 `kRGB565` 临时改成返回 `AV_PIX_FMT_RGB24`，测试立刻红；已还原。

**门禁**：编译零警告；`ctest -j8` **790/790**（+7 新用例，1 条按设计跳过）；
`check_invariants` 13 条**全是存量**（C30 examples 9 + C23 4），我的文件 0 条；
`cpplint` 按 CI 口径（仅 `.cc`）**只剩存量 `base/logging.cc:49`**；

**踩到的两个坑（都记进 MEMORY.md）**：

## 第二轮全树重复扫描（回答「还有吗」）

口径比第一轮宽：扫 `.cc` **和** `.h`、用括号配平取函数体（多行签名不再漏）、
不限函数体长度、把 `Class::Func` 成员定义也纳入、再按 `difflib` 相似度抓「非逐字但
高度相似」的漂移拷贝。**排除 `tools/deps/`**（opus/openssl/srt/libyuv/ffmpeg 等
第三方，不排除会报 179 组假阳性）。

结果：**生产代码（media/base/player/render/platform）里没有该合而未合的函数重复。**
跨文件逐字相同只剩 3 组，全部是「接口约定」而非拷贝：三个 `GlVideoSink`（平台后端）、
三个 `DataSource::Read`（各自转发 `async_`）、`FindSource`（`media/gl` 与 `player` 分属
两层，C28 禁止合并）。近似重复 12 组全是 getter/setter 与 switch 样板。

两条方法学教训：
- 归一化时**剥离了字符串字面量**，所以「函数体完全一致」不保证日志文案一致。
  `OnDecoderStreamEvent` 的两份就是音频/视频对称 + `adec`/`vdec` 不同文案，不是拷贝。
  判断「是不是拷贝」必须回到源码看文案与错误码，不能只看哈希。
- `TEST`/`constexpr`/`ptr_` 这类会被正则误当函数名（491 处假阳性）；gtest 宏与
  `GUARDED_BY` 之类标注要先剔除。

唯一剩下的真实重复在 **`tests/`**（8 组，代价低）：`DestroyRenderer`×3、`SetUp`×5、
`ScriptBuffers`/`StartPlaying`/`PresentFor`/`FramesWithSerial`×2（`video_renderer_impl`
与 `video_renderer_filter_stage` 两个测试）、`PumpUntil`/`PendingBuffers`×2（audio/video
解码器测试）、`WindowRed`/`WindowTopRed`×3、`NewScene`×2、`WaitFor`×2、
`MakeVideoConfig`/`MakeAudioConfig`（`synthetic_demuxer.cc` 与 `synthetic_live_demuxer.cc`）。
顺手核过后者两个文件：35 vs 36 个函数，**只有 2 个函数体相同**（就是这两个 Make*Config），
同名接口实现各不相同，所以它们不是整体拷贝，别按拷贝去合。

## 删掉两个只写不读的字段（用户点名 `waiting_cb_`）

`waiting_cb_` 在三处（`FFmpegVideoDecoderBase`、`FFmpegAudioDecoder`、两个 video 的
`Initialize`）都只赋值、全树无人读。往上看整条链是断的：`DecoderStream` 调用
`Traits::InitializeDecoder` 时传的是**空 `WaitingCB()`**，注释写明「Waiting is
informational here: back-pressure 由 Read() 驱动」。所以是三层死代码（接口参数 +
三个成员 + 三处赋值）。

处置：删成员与赋值，**保留接口参数**（`VideoDecoder`/`AudioDecoder::Initialize` 的签名
与 Chromium 对齐是本项目的目标），参数改成 `/*waiting_cb*/`，并在两个接口头写清为什么
没有后端会调它（FFmpeg 在 `avcodec_send_packet` 内部丢弃直到下一个 IDR，所以「等待关键帧」
永远不会变成一个调用方可以响应的状态；音频则根本没有 stall 状态）。

**`decoding_eos_` 一并删掉**——上一轮我只把注释改成实话（「只写字段、全树无人读」）却没删，
那是不彻底的修法。它唯一的实现就是 `OnEndOfStream()` 里 `decoding_eos_ = true`，所以这次
连同 `FFmpegVideoDecoderBase::OnEndOfStream()` 这个扩展点整个删掉（子类不再需要，基类的
「子类要补四件事」改成三件），「重复 EOS 无害」这条信息移到 `.cc` 的 EOS 分支注释里。

**顺手写了死字段扫描器**（`/tmp/dead_members.py`）：按头文件里的 `name_{...};` 取成员，
统计「所有出现是否都是写」。三个迭代才收敛——第一版把 `x.foo()` 当写（`weak_factory_`
等 146 条误报），第二版漏了头文件里的 inline getter（`audio_buffer.h:duration_` 那样
`{ return duration_; }` 的读不到）。严格版 10 个候选，人工核实后：

- **真死**：`waiting_cb_`×3、`decoding_eos_`（已删）；`renderer_impl.h` 的 `volume_`
  （setter 存一份 + 转发给 AudioRenderer，存的那份无人读）、`pipeline_impl.h` 的
  `tick_clock_`（`SetTickClock` 只存不用）、`ffmpeg_text_decoder.h` 的 `config_`、
  `player_bridge.h` 的 `mailbox_`（setter 里用的是参数不是成员）。**这 5 个没动**，
  等用户定：`tick_clock_` 可能是真问题（注入时钟对 Pipeline 无效）。
- **不是死字段**：`gl_layer_source.h` 的 `displayed_`——不读内容，作用是**持有最后一帧
  的引用**（保活），删了会让帧提前回收；`current_serial_`/`next_chunk_media_time_`/
  `stretch_bus_` 的读在别的 .cc（子类或 `*_ring.cc`），是扫描器的假阳性。
- **有意保留**：`renderer_impl.h` 的 `render_muted_audio_`，注释已说明「media/audio 存在
  之前只存不生效，避免把用户的静音请求静默重解释成 SetMuted()」。
