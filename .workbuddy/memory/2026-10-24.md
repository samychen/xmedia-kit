## 测试 base 功能时发现并修复一个真 bug：PostTaskAndReplyWithResult 数据竞争（未提交）
用户要求"测试 base 目录功能是否有 bug"。跑 base_unittests（149 过）+ 五 demo（全过）后，
核对发现既有测试 DeliversTheValue 只覆盖单 runner fallback（主线程无当前默认序列，
reply 回投同一队列，全程同线程），**根本没验证多序列路径**。据此追查出一个真 bug：

- 原实现在**调用时**就把 reply（done）投到 reply_runner，而结果 value 要等 work 在
  worker 线程跑完才写。跨序列时：worker 写 value 与调用方线程读 value 之间没有任何
  happens-before（reply 队列锁在调用时就已 release，不覆盖 worker 的写）→ 数据竞争/UB。
  单队列单测因全程同线程而掩盖。docs/LEARNING-base.md:1160 亦记"无生产调用方"，故从未触发。

修复 base/task/task_runner_util.h（两分支）：
- 同序列（无默认序列回退 task_runner，或调用方序列==task_runner）：维持调用时投递
  —— 否则 work 执行中新投的 done 其 ready_time 会晚于 RunAllReadyTasks(now) 捕获的 now
  而被 RunNextReadyTask 的 `ready_time>now` 挡掉，导致 received=0（我第一版就是这么
  改挂的，DeliversTheValue 复现）。保留此路是为了保住队列 (ready_time,seq) 排序与单队列 drain。
- 跨序列：由 worker 跑完 work 后从 worker 内部把 reply 投到调用方序列，借 reply 队列锁
  （post release / run acquire）同步写读，消除数据竞争。

  且不判空），video 是 `if (closure) task_runner_->PostTask(...)`。契约（docs/03:475）只约束
  decode_cb，所以 audio 不违规，但 `DecoderStream::Reset` 传的 `OnResetDone` 会同步跑在调用者栈里
  → 潜在重入。改它属于改行为，没测试证明当前有问题，故只记不改。
